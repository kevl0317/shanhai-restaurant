# 山海食谱铺

根据《03_山海食谱铺_网游开发脚本》制作，并按后续需求调整难度与交互的浏览器记忆游戏。经营一间接待山海小客人的食谱铺，记住菜单顺序，按客人的最新要求出餐。

## 启动

**Windows：双击项目里的 `启动游戏.cmd`。** 它会检测已安装的 Node.js 或 Codex 自带的 Node.js，启动服务并打开浏览器；请保持启动窗口打开，按 `Ctrl+C` 停止。若游戏服务已经运行，则直接打开游戏。若未找到运行环境，安装 **Node.js 20 或以上版本** 后再试。

无需安装第三方依赖，也可以在项目目录运行：

```sh
npm start
```

浏览器打开 [http://127.0.0.1:4173](http://127.0.0.1:4173)。`npm run dev` 与启动命令相同；在终端按 `Ctrl+C` 停止服务。请通过 HTTP 地址访问，直接双击 `index.html` 无法可靠加载 JavaScript 模块。

```sh
npm test       # 检查关卡配置、随机出题、菜单更新、计分和阶段时间
npm run build  # 生成 dist/ 静态发布文件，并检查 29 道菜的图片资源
```

将 `dist/` 的完整内容上传到静态网站托管服务即可部署，无需应用服务器或数据库。每次构建都会重新生成 `dist/`，只包含游戏页面、代码、场景与运行时菜品图，不包含试玩测试、开发脚本、美术源图或交付压缩包；请勿把手工文件放入 `dist/`。构建不会自动发布。部署后仍需执行 [验收清单](docs/acceptance-checklist.md) 中的浏览器检查。

## 玩法与范围

- 五章依次为粤菜、川菜、鲁菜、苏菜、浙菜，共 25 关；每关正式任务有 3 笔订单，菜单最多 5 道菜。第 1—10 关每桌最多 20 秒，第 11—20 关每桌最多 24 秒，第 21—25 关每桌最多 26 秒；不含暂停和重试时，每关上限分别为 60、72、78 秒。
- 看单后菜单合上；根据关卡执行替换、取消、加菜或连续改单，再按最终顺序点选。正式关选满后可点“确认出餐”立即提交；保留 2 秒反馈后进入下一单。未手动提交时，配单时间结束自动出餐。
- 正式关和练习均可再次点击菜架中的已选菜品，或点击上方出餐顺序中的已选菜品，取消该菜；取消的位置原位留空，其他菜品的位置不变，再选菜时填入最前面的空位。不再提供独立撤销按钮，选满后仍能取消；已选数量按非空位置计算，取消后正式关的“确认出餐”禁用，补满后重新启用。订单提交进入反馈后不能再改选。
- 提交后逐个位置核对最终菜单：错菜、错序和漏选的每个位置均用边框与标记指出，正确位置不标错；正式关与练习采用相同反馈规则。
- 关前可不限时认识本章 5 道特色菜和 4 道共用菜。第 1、6、11、13、14、19、23、24 关首次进入需完成对应练习；练习不写入正式成绩。
- 通关需至少 2 笔完整正确，并达到顺序还原率门槛：第 1—10 关为 75%，第 11—25 关为 80%。首次通关收集对应名菜卡；章节验收点亮徽章和知识卡，知识互动答对可获得装饰。
- 每次正式关结束自动弹出本关菜品知识卡，角色介绍可继续查看；练习、暂停本身及未完成退出不触发结算知识卡。五位原创伙伴为丹顶鹤清禾、熊猫团团、老虎阿寅、雪豹小霁和龙云生。
- 正式游戏中暂停、切换标签页、窗口失焦或发生影响布局的尺寸变化，会遮住菜单并停止计时，保留本关已完成的桌次和答案。点“继续本关”后，仅未完成的当前桌从记单阶段重来；当前桌已提交则进入下一桌，三桌均已提交则进入结算。暂停本身不产生正式成绩，继续完成三桌后正常计分。
- 练习也可以暂停后继续；未提交的练习桌从记单阶段重来，已提交的练习反馈保留。退出到小铺或刷新页面仍会放弃进行中的本关，不保存可跨页面恢复的临时进度。

当前版本为**浏览器单人游戏**：本地 HTTP 服务只负责提供静态文件，未接入账号、多人联机或云存档。成绩、收藏、装饰和设置保存在当前浏览器的 `localStorage`；更换浏览器、访问地址或清除网站数据会影响进度读取。

首页关卡列表下方提供“导出存档”和“加载存档”，操作方式与熊猫快递局相同：导出 JSON 文件备份或分享，在另一浏览器加载后继续游玩。文件包含关卡成绩、已完成练习、已获得装饰及摆放位置，菜卡根据通关记录恢复。加载时合并进度并保留更高成绩，保留接收端的音效、动效设置和已有装饰摆放；不转移正在进行的一桌或最近订单回放。只接受山海食谱铺格式且不超过 100 KiB 的存档；不兼容文件、损坏文件或浏览器保存失败均不会改动原有进度。

## 难度安排

| 关卡 | 每桌上限 | 记单时间 | 每条改单时间 |
| --- | --- | --- | --- |
| 第 1—10 关 | 20 秒 | 沿用原配置 | 2.5 秒 |
| 第 11—20 关 | 24 秒 | 6—6.5 秒 | 3 秒 |
| 第 21—25 关 | 26 秒 | 7 秒 | 3 秒 |

前十关难度保持不变，后续章节总体递增，章内保留认识新规则的教学缓冲。第四章每桌最多一次改单；第五章第 23、24 关有两处改动，在同一页一起展示 6 秒，取消与新增/替换位置同时可见，编号使用最终顺序。练习中点击一次“继续”即可出餐。各桌均保留 2 秒反馈，选满后仍可提前确认出餐，通关分数与至少两桌全对的要求不变。

- 第 17 关“四道变五道”：记住 4 道菜后加 1 道，最终 5 道。
- 第 19 关“中间换一道”：只将第 3 道换菜一次。
- 第 21 关“五道菜上桌”和第 22 关“五道中的新菜”：初始菜单均为 5 道。
- 第 23 关：先取消第 2 道，再在当前第 4 道前插入新菜，最终 5 道。
- 第 24 关：分别替换第 2 道和第 4 道，共两次改单，最终 5 道。
- 第 25 关：记单 7 秒、等待 0.5 秒，5 道菜配一次改单。

上述难度与逐位置错误标记是 2026-09-23 的最新修订，验收状态见 [验收清单](docs/acceptance-checklist.md)；旧版六道菜单和连续换第 3 道的实测记录不代表新版已通过。

## 文件与资源

| 路径 | 内容 |
| --- | --- |
| `src/app.js` / `styles.css` | 页面、交互和响应式样式 |
| `src/engine.js` | 25 关配置、带随机种子的出题、计时阶段与评分 |
| `src/storage.js` | 本地进度、最高成绩、最近一次完整成绩 |
| `src/content.js` | 29 道菜及 5 章知识、徽章、装饰、互动题目 |
| `src/characters.js` | 五位小铺伙伴的介绍与章节分工 |
| `assets/` | 铺面、五位伙伴、装饰及章节徽章 SVG |
| `art/dishes-v1/` | 已绘制的菜品美术、资源清单及生成说明 |
| `tests/` | Node.js 内置测试框架的自动化测试 |

运行时使用 `icons-256/` 与 `sprites-1024/` 中的透明 PNG。25 条菜品知识与 5 条章节知识沿用开发脚本；4 道共用菜不归属于某一菜系。原始开发脚本保留在项目根目录，资源说明见 `art/dishes-v1/README.md`。

Git 远程 `origin` 已关联 [kevl0317/shanhai-restaurant](https://github.com/kevl0317/shanhai-restaurant)。本次游戏实现尚未提交或推送。美术交付压缩包 `art/*.zip`、构建产物 `dist/` 与本机试玩文件 `playtest/` 已加入 `.gitignore`，菜品 PNG 源资源保留在项目中。
